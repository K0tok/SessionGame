# План разработки: «Сессия» (hot-seat, Android, Java)

Формат: hot-seat (одно устройство), 2–4 игрока.  
Цель: первым закрыть три экзамена и успешно пройти финальную защиту.  
Стек: Android Studio, Java.  
База данных: **не нужна** (контент — JSON в `assets/`, партия — память + при необходимости файл / SharedPreferences).

---

## Роли

| Роль | Фокус |
|------|--------|
| **Core / Logic** | модель, ходы, кубик, карты, квесты, сохранение, unit-тесты |
| **Никита — UI / Content** | экраны, поле, анимации, вопросы/задания, UX hot-seat |

**Правило:** UI не содержит правил игры. Все решения («кто ходит», «начислить балл», «пропустить бросок») — только в `GameController` / модели.

```
UI (Никита)  ←→  GameController  ←→  Model
                ↓
         ContentRepository
         (вопросы, карты, события из JSON/assets)
```

---

## Этап 0. Каркас проекта (совместно)

**Срок:** 1–2 дня

1. Создать проект Android Studio (Java, minSdk 24+, актуальный targetSdk).
2. Задать пакетную структуру: `model`, `controller`, `ui`, `content`, `util`.
3. Сделать один экран-заглушку и навигацию между пустыми экранами.
4. Договориться о контрактах: имена классов, события UI ↔ логика.
5. Настроить Git: A не трогает `res/` и Activities без договорённости; B не правит `controller/` и `model/` без договорённости.

**Итог:** оба могут работать параллельно без конфликтов в одних файлах.

## Этап 1. Модель игры + UI лобби (параллельно)

### Core

1. Класс `Player` (имя, цвет/фишка, позиция, баллы по 3 дисциплинам, карты в руке).
2. Класс `Board` (замкнутый маршрут из 20 клеток, тип каждой).
3. Enum `CellType`: START, EXAM, SABOTAGE, EVENT, BREAK, PRACTICE, BLITZ.
4. Enum `ExamDiscipline`: IT, ENGINEERING, NTI_LIFE.
5. Класс `GameState` (очередь хода, фаза партии).
6. Карты: `StolenNotes`, `ExtraTicket`, `Automat`.
7. Класс `Dice` (бросок 1–6).

### Никита — UI

1. Экран создания партии: 2–4 игрока, имена, выбор цвета фишки.
2. Экран кратких правил.
3. Кнопка «Начать игру» → переход на игровое поле (пока заглушка).

**Итог:** можно создать сессию с игроками; модель живёт без UI.

---

## Этап 2. Ходы по полю + визуал поля (параллельно)

### Core

1. Логика броска и перемещения по кольцу из 20 клеток.
2. Эффект пропуска хода («Украденный конспект»).
3. Смена активного игрока.
4. Listener/callback для UI: `onMoved`, `onTurnChanged`, `onCellEntered`.

### Никита — UI

1. Визуал замкнутого маршрута (20 клеток, иконки типов).
2. Анимация фишек по клеткам.
3. Кнопка «Бросить кубик» + анимация куба.
4. Панель: чей ход, зачётка (баллы по 3 экзаменам).

**Итог:** игроки ходят по кругу; при входе на клетку — заглушка с типом клетки.

---

## Этап 3. Экзамены и финальная защита

### Core

1. Начисление зачётных баллов по дисциплинам (цель: 3 балла × 3 направления).
2. Выбор дисциплины для клетки «Экзамен» (рандом / ротация / выбор — зафиксировать в ТЗ).
3. Условие допуска к финальному вопросу (все три экзамена закрыты).
4. Финальный вопрос → победа («сессия сдана») или провал (правило штрафа зафиксировать).

### Никита — UI

1. Диалог вопроса: текст, варианты ответа / ввод.
2. Экран прогресса зачётки.
3. Экран победы.

### Контент

- Схему JSON задаёт Core; наполнение — Никита.

Пример схемы:

```json
{
  "id": "it_001",
  "discipline": "IT",
  "question": "Текст вопроса",
  "answers": ["A", "B", "C", "D"],
  "correctIndex": 0
}
```

**Итог:** основная победа по правилам работает (MVP).

## Этап 4. Карты и остальные клетки

| Клетка / механика | Логика | UI (Никита) |
|-------------------|------------|--------|
| Саботаж | Выдать карту в руку | Диалог «получить карту» |
| Украденный конспект | Выбор цели, skip next roll | Выбор соперника |
| Дополнительный билет | Вопрос 15 сек, −2 клетки при ошибке | Таймер + вопрос |
| Автомат | Отмена одной карты саботажа | Кнопка «использовать защиту» |
| Перемена | Выдать защитную карту «Автомат» | Уведомление |
| Событие | Таблица случайных эффектов | Карточка события |
| Практика | Проверка задания (верно/неверно) | Экран задания |
| Блиц | Вопрос с жёстким таймером | UI таймера |

**Итог:** полный цикл клеток без мировых квестов.

## Этап 5. Мировые квесты

Шанс запуска на любом ходе (например 10–15%, настраиваемо).

1. **Спасение лаборатории** — общая задача, 30 сек; при majority правильных ответов — награда всем.
2. **Кто быстрее?** — задание участникам по очереди (hot-seat); победитель быстрее всех с верным ответом получает +1 зачётный балл.
3. **Внеплановая сессия** — отдельный вопрос каждому; ошибка — без награды, успех — бонус.

### Core

1. Три режима в контроллере.
2. Таймауты и награды.
3. Интеграция шанса в любой ход.

### Никита

1. Полноэкранные режимы квестов.
2. Явная смена игрока («Передай устройство»).

**Итог:** мировые испытания работают на одном телефоне.

2. Unit-тесты правил (ходы, баллы, карты, финал).

### Никита

1. Кнопка «Продолжить игру».
2. Звуки (по желанию), иконки, визуальный стиль.
3. Smoke-чеклист UI на 2–4 игроках.
4. Наполнение контента: минимум ~30 вопросов на дисциплину, ~10 событий, ~10 практик.

### Совместно

1. Плейтест и балансировка.
2. README / краткая инструкция.
3. Сборка APK и демо.

## Данные: почему без БД

| Что хранить | Как |
|-------------|-----|
| Вопросы, карты, события | JSON в `assets/` |
| Текущая партия | Объекты в памяти |
| Продолжение партии | Файл / SharedPreferences |
| Баллы зачётки | Поля в `Player` |

БД понадобится только при онлайне, аккаунтах, большой статистике или встроенном редакторе контента.

## Риски

| Риск | Решение |
|------|---------|
| Путаница «чей ход» на одном телефоне | Экран «Ход: Имя» + кнопка «Готов» |
| Блиц / «кто быстрее» на одном устройстве | Очередь: каждый отвечает на своём экране, фиксируется время |
| Конфликты в Git | Разделение зон: Core / Никита |
| Мало контента | Квоты на вопросы/события/практики до этапа 6 |
